# Chaoscope for iOS

The iOS app — a **SwiftUI** front-end over the same C++ render engine in
[`core/`](../core/) used by Android. The engine is reached through a thin **plain-C
bridge** (`ios/Core/chaoscope_c.cpp`) imported by the Swift bridging header.

> **Status:** builds in CI (simulator + unsigned device `.app`) and has been confirmed
> running on a physical iPad via sideload. UI parity with Android is still in progress.
> See the [root README](../README.md) for the project overview.

---

## Architecture

```
SwiftUI UI                    (ContentView, DotCanvas, ChaoscopeApp)
      │
      ▼
RenderViewModel.swift          (render state)
      │
      ▼
ChaoscopeEngine.swift          (Swift wrapper over the C bridge)
      │   imports via Sources/BridgingHeader.h
      ▼
ios/Core/chaoscope_c.{h,cpp}   (extern "C" bridge — the only C++ allowed to touch Swift)
      │   #include "renderer.h"
      ▼
core/renderer.cpp + core/attractors.cpp   (shared portable engine — see ../core)
```

`chaoscope_c.h` is **pure C** (no C++) so the Swift bridging header can import it; the
matching `chaoscope_c.cpp` is the only translation unit that converts between the C
struct (`ChaoscopeRenderParams`) and the engine's C++ `RenderParams`, then calls
`renderAttractor()`, `getProjectedPointsDepth()`, and `getPaletteLutARGB()` from
`core/`.

### Source layout

```
ios/
├── project.yml          ← XcodeGen project spec (the .xcodeproj is generated, not committed)
├── Core/
│   ├── chaoscope_c.h     ← plain-C interface (struct + render/preview/palette entry points)
│   └── chaoscope_c.cpp   ← C↔C++ bridge into core/
└── Sources/
    ├── ChaoscopeApp.swift     ← @main app entry
    ├── ContentView.swift      ← root SwiftUI view
    ├── DotCanvas.swift        ← dot-cloud preview rendering
    ├── RenderViewModel.swift  ← render/UI state
    ├── ChaoscopeEngine.swift  ← Swift wrapper over the C bridge
    ├── AttractorDefs.swift    ← attractor/palette defs (ordinals match core + Kotlin)
    └── BridgingHeader.h       ← imports Core/chaoscope_c.h into Swift
```

The shared engine is pulled in by `project.yml`, which adds `../core` as both a source
path (compiled with `-std=c++17 -ffast-math`) and a header search path. The
Android-only files (`gpu_renderer.*`, `chaoscope_jni.cpp`) are not in `core/`, so iOS
never sees them.

## Building

The `.xcodeproj` is **generated** from `project.yml` — don't edit or commit it.

```bash
cd ios
xcodegen generate            # produces Chaoscope.xcodeproj

# Simulator build (fast compile check, no signing)
xcodebuild \
  -project Chaoscope.xcodeproj \
  -scheme Chaoscope \
  -sdk iphonesimulator \
  -configuration Release \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO
```

Then open `Chaoscope.xcodeproj` in Xcode to run on a simulator or device.

### Sideloading to a real device (no paid Apple Developer account)

CI produces an **unsigned `.ipa`** (see below) that can be re-signed locally with
**Sideloadly** (Windows/macOS) or **AltStore** using a free Apple ID for 7-day
sideloading. This is the supported path for running on a physical device without a
paid developer membership.

## Continuous integration

[`.github/workflows/ios-build.yml`](../.github/workflows/ios-build.yml) runs on every
push/PR to `main` (on `macos-15`, Apple-Silicon, Xcode 16.x):

1. `brew install xcodegen` → `xcodegen generate`
2. Simulator build (compile check, no signing)
3. Unsigned device build (`ARCHS=arm64`, no signing)
4. Packages an unsigned `Chaoscope-unsigned.ipa` and uploads it as a build artifact
   (14-day retention)

## Notes & known gaps

- **format-77 project files:** Xcode 16 writes project files at `objectVersion = 77`,
  which older Xcode can't open. The project is regenerated by XcodeGen, so this only
  matters if you commit a `.xcodeproj` (don't — it's generated).
- **UI parity:** the iOS UI does not yet match the Android feature set (export modes,
  palette editor, tutorial, etc.). The shared engine is fully functional; the gap is in
  the SwiftUI layer.
- **Engine changes are shared:** editing anything in [`core/`](../core/) affects Android
  too. Keep `core/` free of platform headers.
